# EV80-diag 0.4.0: Van Profiles + Mark a Moment, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** several van profiles with their own data, automatic van recognition (switch when clear, ask when unclear), add/edit/delete a van, and a text-only "mark a moment". The owner drives ET and Lytee in the coming weeks.

**Architecture:**
- The pipeline no longer takes a fixed profile. It starts on the active van and runs a pure `VanRecognizer` on the first odometer / charge-counter values of each connection.
- Data recorded before the decision is moved to the recognised van:
  - the open session;
  - cell snapshots since the connection started.
- The app SOC estimate is per van and paused until the van is confirmed.
- All screens read the active van from one `ActiveProfile` flow instead of "the first profile".

**Tech Stack:** unchanged (Kotlin, Compose/Material 3, Room 2.8 with auto-migration, JUnit 4).

**Spec:** `docs/specs/2026-11-03-ev80-diag-app-design.md` §5.1 (Connect / profiles), §5.9 (Mark a moment), §11 stage 3.

**Owner decisions (2026-11-05):**
- Recognition switches automatically when exactly one van clearly matches, shows a note ("Switched to Lytee · Undo"), and asks only when unclear. This overrides the spec's "suggestion only".
- No "move session to another van" in 0.4; revisit in the next version.
- No van colour ("all EV80s are traffic white"). The tile layout is shared by all vans (it was per van in 0.3: the first van's layout becomes the shared one).
- Text-only "mark a moment" is in.
- Not in 0.4:
  - backup/restore (Export all already gets the data out);
  - Experimental screen (raw monitor, unconfirmed signals);
  - first-start flow;
  - update hint.

   - the session row;
   - its cell snapshots;
   - nothing fed into the wrong van's SOC.

   Pinned in Task 4 (`twoVans_counterMatchesOther_switchesAndMovesData`).
2. **The `0x380` all-zero wake frame** (odometer 0) is no evidence. With it, a van with odometer 0 would match nothing and every connection would ask. Pinned in Task 2 (`zeroOdometer_isNoEvidence`).
3. **Undo after an automatic switch** moves the data back and does not switch again in the same connection. Pinned in Task 4 (`undo_movesBack_noSecondSwitch`).

### Task 2: VanRecognizer (pure)

**Files:**
- Create: `profile/VanRecognizer.kt`
- Test: `test/.../profile/VanRecognizerTest.kt`

**Interfaces:**
- `data class VanPrint(val id: Long, val lastOdoKm: Double?, val lastChargeKwh: Double?)`
- `sealed interface Recognition`:
  - `data class Match(val id: Long, val by: Evidence)`
  - `data class Unclear(val candidates: List<Long>)`: the candidates are the vans that fit, or all vans when none fits
  - `data object NoEvidence`
- `enum class Evidence { ODOMETER, CHARGE_COUNTER }`
- `object VanRecognizer`:
  - `fun recognize(vans: List<VanPrint>, odoKm: Double?, chargeKwh: Double?): Recognition`
  - `const val MAX_ODO_GAP_KM = 3_000.0`
  - `const val MAX_CHARGE_GAP_KWH = 300.0`

**Rules:**
- A known value fits when `last − 0.2 ≤ seen ≤ last + gap`.
  - Odometer is checked when `odoKm > 0`.
  - Counter is checked when `chargeKwh > 0`.
  - If both are seen, both must fit.
- A van with neither value known is "unseen".
- **Decision:**
  1. Exactly one seen van fits → `Match`.
  2. Otherwise, if no seen van fits and exactly one van is unseen → `Match` with that van (a newly added van).
  3. Otherwise → `Unclear`.
- No values at all → `NoEvidence`.
- **One van only:** the caller never asks (spec: "with one van the app never asks").

**Interfaces:**

  - `suspend fun vans(): List<VanPrint>`
  - `suspend fun moveConnectionData(sessionId: Long?, from: Long, to: Long, sinceMs: Long)`: covers the session, cell snapshots and marks
  - `suspend fun setLastSeen(profileId: Long, odoKm: Double?, chargeKwh: Double?, ms: Long)`
  - `suspend fun addMark(m: MarkEntity)`
- **Pipeline constructor:**
  - `profileId: Long` becomes `startProfileId: Long`;
  - new `recognize: Boolean = true`, false for replays (a replay never switches vans and never writes last-seen values).
- **New members:**
  - `val profileId: StateFlow<Long>`
  - `fun chooseProfile(id: Long)`: answer to Ask, Undo, or a tap on a van card while connected
  - `RecorderState.profileEvent: ProfileEvent?`, where `sealed interface ProfileEvent` is:
    - `Switched(from: Long, to: Long, by: Evidence)`
    - `Ask(candidates: List<Long>)`
  - `RecorderState.profileConfirmed: Boolean`
- **Behaviour:**
  - At connection start: one van → confirmed at once.
  - Otherwise, on each decoded `odo_km`/`charge_counter` until decided, call `VanRecognizer.recognize`:
    - `Match` on the active van → confirmed, no event;
    - `Match` on another van → move the connection's data (`sinceMs` = first frame of this connection), switch, confirmed, event `Switched`;
    - `Unclear` → event `Ask`, stays unconfirmed (recording goes on into the active van; SOC paused).
  - `chooseProfile` moves the data the same way, sets confirmed, and clears the event. After a choice or a decision, no further recognition in this connection.
  - Every 60 s while confirmed (and at session end): `setLastSeen` with the latest values > 0.
  - **`mark(text)`:**
    - adds a `MarkEntity(profileId, openSessionId, ts, text)`;
    - keeps writing the `.marks` file when a raw log is open.
